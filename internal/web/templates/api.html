API contracts

Two public endpoints of the Credits service, called by the AI Gateway on behalf of a vendor app. Below them: the events we take from Billing. Both endpoints are live on this server.

POST /api/v1/credits/charges

Charge one AI action. Credits are taken at the start for the fixed price of the action and returned only on a failure on our side.

Headers
  Idempotency-Key: <uuid, one per user action;
                    the same on every retry>
  X-Customer-Id:   <customer, set by the Gateway>

Request
{
  "application_id": "uuid",
  "action_code":    "ai.generate",
  "input":          { … }
}

Response 201
{
  "charge_id": "uuid",
  "status":    "completed",
  "charged":   80,          // credits taken
  "available": 9920,        // left for THIS app
  "result":    { … },       // AI result
  "blocked":   false        // content policy: still charged
}
CodeerrorMeaning
200—Replay: the key was already completed, the stored result comes back, nothing is charged again
400idempotency_key_requiredNo Idempotency-Key header
400customer_requiredNo or malformed X-Customer-Id
400invalid_application_idMissing or not a uuid. Nothing is charged
402insufficient_creditsNot enough credits usable in this app; available and required in the body. Nothing is stored
403no_active_licenseThe customer has no active license for this app
403account_blockedWallet blocked (chargeback)
404unknown_actionNo price for this (app, action)
404unknown_customerNo wallet for the customer
409in_progressThe same key is still running; retry later with the same key
409lot_changed_retryA lot changed under the debit; safe to retry with the same key
422idempotency_key_reusedThe same key with a different body
502upstream_failedProvider 5xx; credits already returned, refunded: true
502timed_outProvider answered after the sweeper had returned the credits; refunded: true

Rules: a known key answers before any other check, so a retry after a refund still gets its 200. One key = one charge, whatever the number of parallel copies.

GET /api/v1/credits/balance?application_id=…

What the customer can spend here, and where the rest of the balance sits. Answers "why does the site show 10 500 and the app 500".

Headers
  X-Customer-Id: <customer>

Response 200
{
  "application_id": "uuid",
  "available": 500,          // usable in this app
  "total":     10500,        // whole wallet
  "by_source": [
    { "label": "Design+ bundle · Oct 26",
      "source": "bundle", "scope": "bundle",
      "kind": "paid", "remaining": 10000,
      "applies_here": false,
      "expires_at": "2026-11-26T…" },
    { "label": "Credit pack 500",
      "source": "pack", "scope": "platform",
      "kind": "paid", "remaining": 500,
      "applies_here": true,
      "expires_at": "2027-10-27T…" }
  ]
}
CodeerrorMeaning
200—Without application_id: the whole wallet (the site's view), available = total, no applies_here filter
400customer_requiredNo or malformed X-Customer-Id
400invalid_application_idapplication_id is not a uuid
404unknown_applicationNo such app. Never answered as "0 here": the app would show a wrong balance
404unknown_customerNo wallet for the customer

EVENTS from Billing → our grant handler

Billing owns webhooks, subscriptions and payments. We take three domain events, at-least-once, possibly duplicated or out of order.

PaymentSucceeded {
  payment_id, subscription_id, offering_id,
  customer_id, period_start, period_end, amount
}
PaymentRefunded {
  payment_id, refund_amount
}
SubscriptionCanceled {
  subscription_id, at_period_end
}
EventWhat we do
PaymentSucceededOne transaction: a license per plan item (UK subscription + item; renewal moves due_date), a lot per credit item (UK payment + item). A duplicate grants nothing
PaymentRefundedRevoke the lots of that payment; licenses end with the earlier paid period. Unknown payment_id → retry, not drop
SubscriptionCanceledCancel at period end: licenses and lots live until their own dates, no renewal grants new ones

We ask Billing for: a stable payment_id across retries, replay of events by payment_id / subscription_id, and kind = one_time subscriptions for credit packs.

Try it

curl -X POST https://credit-and-bundle.ihatebot.com/api/v1/credits/charges \
  -H 'X-Customer-Id: <customer uuid>' -H 'Idempotency-Key: '$(uuidgen) \
  -H 'Content-Type: application/json' \
  -d '{"application_id":"<app uuid>","action_code":"ai.generate","input":"cat"}'

curl 'https://credit-and-bundle.ihatebot.com/api/v1/credits/balance?application_id=<app uuid>' -H 'X-Customer-Id: <customer uuid>'

Customer and app uuids are on the Data page (tables customers, applications). Every call shows up live in the Simulator log.
